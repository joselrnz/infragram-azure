# themes/

Provider presets, one JSON file each. A theme is everything needed to redraw
the architecture example in a provider's visual language — it owns no library
artwork, only its identity badges in `marks/`.

```text
themes/
├── catalog.json        ordered theme index (schema v2): azure.json, kubernetes.json
├── <slug>.json         the whole manifest for one provider
├── generic.json        the neutral theme the core frames draw in; belongs to no library
└── marks/<slug>.svg    recolorable 24x24 badges (currentColor, aria-hidden)
```

`generic.json` is not a provider: it is listed in no catalog and registers
no library. It carries only the canvas colours and a `boundaries` block, so
a core frame (site, DMZ, environment, ...) placed inside an Azure or
Kubernetes project keeps the same neutral grey in both renderers.

## <slug>.json

| Field | Required | What it does |
|---|---|---|
| `theme` | yes | 7 canvas colors + optional `corners` (square / rounded / circular) |
| `services` | yes | name + detail for the four example roles (entry, app, object_store, database) |
| `mark` | yes | `marks/<slug>.svg` (theme-owned, recolorable badge) or a library reference such as `logos:kubernetes#mono` |
| `icons` | yes | inline vocabulary: `{"categories": [...], "items": [...]}` (items may be empty) |
| `icon_palette` | no | colors the provider's icons are allowed to use |
| `service_icons` | no | which icon renders in each role's box (all four or none) |
| `boundaries` | no | shared `ClusterStyle` preset for topology builders: independent colors, fills, dashes, widths, radii, tabs, icons, and forbidden ambiguous kinds |

Every `items` entry references artwork in [`../icons/`](../icons/) by a
**qualified** `asset_ref` — `vendors/azure/virtual-machine`, or `logos/nginx#mono` for a
logo (the variant is mandatory so the digest pin stays reproducible). A theme
entry adds only what the library cannot know: the curated id, the
diagram-facing category, and human aliases (`"vnet"`, `"blob"`, `"aks"`).

## Why marks are not logos

A mark is a hand-normalized derivative: `fill="currentColor"` so it inherits
the theme's accent, `aria-hidden` so it stays out of the accessibility tree,
layout-free so the renderer owns placement. Raw logos in `../icons/logos/`
carry fixed fills and are wholesale-regenerated by the importer — unfit for
deterministic, recolorable badges.

## Adding a provider

1. If it has an official icon pack, register it in
   `../icons/vendors/sources.json` and run
   `python scripts/importers/official-icons.py <slug>`.
2. Write `themes/<slug>.json` (fields above) and a normalized
   `themes/marks/<slug>.svg`; list `<slug>.json` in `themes/catalog.json`.
3. Rebuild and check: `infragram build:examples build:index`, then
   `infragram test:catalog test:providers`.

Azure boundary changes belong in `azure.json` under `boundaries`, not in an
example build script. `build_topology(..., theme="azure")` merges that preset
under caller overrides automatically. Keep every zone map complete and
independent; a color entry never implies a dash, width, radius, or fill.
